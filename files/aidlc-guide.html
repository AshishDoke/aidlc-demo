AIDLC: AI-Driven Life Cycle

A framework that takes a requirement all the way to a merge request using AI coding assistants (Claude Code or GitHub Copilot), with humans approving every important decision and every step logged.

InputA requirement: a Markdown file or a Jira ticket, e.g. LT-001
OutputA feature branch with code, tests and a sealed evidence record, ready for a merge request
In betweenSpec → design → plan → code → tests → review, with 3 human approval gates
Works withClaude Code and GitHub Copilot (agent mode). You can switch tools mid-way
The one idea to remember: the AI does the thinking work. A small, boring script (aidlc.py) enforces the rules. Humans make the decisions.

Why it exists

Problem with "just ask the AI to build it"How AIDLC solves it
AI may skip steps, misunderstand the requirement, or drift out of scopeA fixed lifecycle with checks the AI cannot skip, plus a scope fence on which files may change
Nobody knows what the AI did or whyAppend-only audit log: every stage, decision, tool call and approval, with who did it
No human control before code is writtenHuman gates: approve the spec (G1), the design (G2) and the final result (G3)
Long tasks break when the chat endsWorkflow state is saved to files, so you can resume any time, from any tool
Each AI tool behaves differentlyThe same instructions and the same engine for Claude and Copilot

Architecture

Four layers. Purple can make mistakes. Green enforces the rules. Grey is people and data.

Where is the "orchestrator"?

It's split in two on purpose. The loop driver is the AI running the aidlc-run skill: it keeps asking "what next?" and does the work. The brain is aidlc.py next/complete: it decides. Because the brain is the same script for every tool, Claude and Copilot behave the same way.

Lifecycle and gates

INTAKE→ANALYZE→G1 spec→ DESIGN→G2 design→PLAN→IMPLEMENT→ TEST→REVIEW→G3 raise MR→MR→DONE (sealed)
StageWhoProducesChecked by the script before moving on
INTAKEscriptrequirement.md (a verbatim copy)Dependencies merged, clean working tree, creates branch aidlc/<ID>
ANALYZEAIspec.mdRequired sections present, numbered AC1, AC2…
G1humanapprovalBound to the spec's hash
DESIGNAIdesign.mdSections incl. "Affected files", no code changes yet
G2humanapprovalBound to the design's hash
PLANAIplan.md with tasks + allowed_filesEvery AC covered by a task, scope not too broad, no protected paths
IMPLEMENTAIone commit per task [ID][T1]…All tasks committed, only allowed files changed, no secrets
TESTAI + scripttest-report.mdThe script runs the tests itself, every AC has evidence, no skipped tests
REVIEWAIreview.mdGuardrail scan clean, passing tests recorded
G3humanapprovalBound to the review's hash and the exact commit
MRAI + scriptmr.md + sealed recordNo new commits after G3. The run is copied to .aidlc/records/ and committed
Approvals are locked to content. If someone edits an approved spec or design, or adds a commit after G3, the approval is revoked automatically and the run goes back to that stage.

Live vs sealed: runs/ is the working memory and survives branch switches. records/ is the evidence that travels with the merge request.

How one loop works

Every stage follows the same 4-beat rhythm:

  1. AI runs python tools/aidlc/aidlc.py next LT-001 --client claude-code
  2. script reads state.json and answers in JSON: which stage, which skill file to follow, which inputs to read, and which files the AI may write. 
    { "action": "DO_STAGE", "stage": "ANALYZE",
  "skill": ".aidlc/skills/analyze.md",
  "inputs": [".aidlc/runs/LT-001/artifacts/requirement.md", ".aidlc/context/project.md"],
  "output": ".aidlc/runs/LT-001/artifacts/spec.md",
  "allowed_paths": [".aidlc/runs/LT-001/artifacts/spec.md"] }
  3. AI does the work by following the skill, and writes the output.
  4. AI runs aidlc.py complete LT-001 --stage ANALYZE. The script checks the output, logs it, and either moves on or says STOP (a gate needs a human).

When it says STOP, the AI tells you what to review. You approve in your own terminal, then type /aidlc-run LT-001 to resume.

Worked example: LT-001

Requirement (requirements/LT-001.md): "Create the .NET solution, a health endpoint, a SQLite database with employees and leave requests, and seed demo data." Here is the whole journey.

  1. You In Claude Code type /aidlc-run LT-001 (in Copilot: run the /aidlc-run prompt).
  2. script Copies the requirement into requirement.md, creates branch aidlc/LT-001 and state.json, and logs run.created.
  3. AI ANALYZE: reads the requirement and project context, writes spec.md: 
    ## Acceptance criteria
- AC1: The solution builds and GET /api/health returns 200
- AC2: On first start leave.db is created with Employees and LeaveRequests tables
- AC3: Seed creates 1 manager + 3 employees; restarting does not duplicate them
## Open questions
- Q1: Is email unique? Assumption: yes
  4. script Checks the sections and ACs → STOP: G1 needed. AI tells you: "please review spec.md".
  5. You Read the spec. Not happy? python tools/aidlc/aidlc.py reject LT-001 G1 --comment "Make email uniqueness an AC". The AI gets your comment in feedback.md and fixes the spec. Happy? python tools/aidlc/aidlc.py approve LT-001 G1 → type APPROVE.
  6. You /aidlc-run LT-001 → AI DESIGN: design.md lists exact files (e.g. app/src/LeaveTracker.Api/Data/AppDbContext.cs) → STOP at G2 → you approve.
  7. AI PLAN: tasks plus the scope fence: 
    {"tasks":[{"id":"T1","title":"Solution + API + health","covers":["AC1"]},
          {"id":"T2","title":"DbContext + entities + seed","covers":["AC2","AC3"]}],
 "allowed_files":["app/LeaveTracker.sln","app/src/LeaveTracker.Api/**","app/tests/LeaveTracker.Tests/**"]}
  8. AI IMPLEMENT: commits [LT-001][T1] Solution, API and health endpoint, then [LT-001][T2] …. If the chat stops after T1, the next /aidlc-run (even from Copilot) continues at T2.
  9. AI + script TEST: the AI adds tests and writes test-report.md (AC → test). The script then runs dotnet test itself. A failure keeps the stage open.
  10. AI REVIEW: runs aidlc.py check (scope, secrets, skipped tests), writes review.md with an honest recommendation → STOP at G3.
  11. You Check git log main..aidlc/LT-001 and the review, then approve LT-001 G3.
  12. AI + script MR: writes mr.md (summary, AC checklist, AI disclosure). The script seals everything into .aidlc/records/LT-001/ and commits it.
  13. You Push and merge (git merge --no-ff aidlc/LT-001 or a GitLab MR). CI runs verify. Now LT-002 is unlocked.

Guardrails

Humans approveAI can't run approve/reject. The script refuses inside AI sessions and needs a real terminal.
Scope fenceOnly files in the approved plan may change. Claude is blocked live; everyone is re-checked at complete and in CI.
Protected filesRules, skills, engine, CI and requirements can't be changed by an AI run.
Honest testsThe script runs the tests. Skipped, deleted or fake tests are detected.
No secretsAdded lines are scanned. Secrets are redacted from logs.
LimitsMax files, lines and tasks per requirement. 5 failed attempts → BLOCKED for a human.
Git safetyNo merge, rebase, force-push, amend, config changes, --no-verify, or push to main.
Tamper-evidentHash-chained log and hash-bound approvals, verified in pre-push and CI.
Kill switch and lockshalt stops everything. One AI per requirement at a time.

Using it on an existing repo

  1. Copy tools/aidlc/, .aidlc/, .githooks/ and the CI job. Merge .claude/, .github/ and AGENTS.md with what you already have.
  2. Edit .aidlc/config.json: base branch, test command, Jira key pattern, limits.
  3. Write .aidlc/context/project.md: purpose, architecture, conventions, build/test commands, do-not-touch areas. This is how the AI knows the background.
  4. Add repo-specific protected paths (generated code, shared libraries) to guardrails.json.

How does it know where to change code? The AI explores the codebase in ANALYZE/DESIGN and lists the exact "Affected files". You check that list at G2. It then becomes the scope fence the script enforces.

FAQ and glossary

Does anything run in the background?

No. The workflow moves only while an AI chat is running /aidlc-run. Between sessions, everything waits safely in the state files.

Can I switch from Claude to Copilot halfway?

Yes. The state lives in files, not in the chat. The audit log records which tool did each stage.

What if the AI edits something it shouldn't?

Claude is blocked immediately by a hook. For Copilot, the script's git-diff check fails the stage, and CI fails the MR.

Can the AI fake an approval?

It's blocked several ways locally, but a determined process on the same machine could forge files. For full assurance, approvals should come from GitLab MR approvals or Jira (a planned enhancement).
